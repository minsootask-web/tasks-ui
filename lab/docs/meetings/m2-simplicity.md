# 2차 회의 — 심플함 수호자(사용자 대변) 의견서

작성: 심플함 수호자 · 2026-10-20
자료: `m2-agenda.md`, `m1-minutes.md`, `../05-usability1.md`(완성도 7.5), `../04-qa2-review.md`(R1~R22)
기준은 1차와 같다. ① 늘 보이는 요소가 늘어나는가 ② 외울 규칙이 늘어나는가 ③ 1인 사용자가 매일 겪는 문제인가. 남은 예산은 **늘 보이는 요소 1개, 새 규칙 0개**다.

## 0. 1차 구현은 심플함 합격선(순감소)을 지켰나 — **판정: 통과**

| 구분 | 항목 |
|---|---|
| **빠진 것** (늘 보이던 것) | 모바일 행마다 ⋮⋮·×(High 20개 이상 기준 40개 이상), ⇅ 정렬, 평소의 저장 표시, FAB(Task 외 3개 탭), 확인창 4종, 성공 토스트, Inbox H/M/L 글자(🍅🍋🥝로 교체), 선택 모드의 행 버튼, 섹션 헤더 영어 대문자, 우선순위 표기 3종 |
| **늘어난 것** (늘 보이는 것) | 섹션별 "완료 n개" 접기 행(예산 1번) · Archive 행의 날짜 "3일 전"(B14 합의) · Archive 행의 하위 개수 "+1"(**예산 밖**) · Inbox 선택 바의 ✕(감사 B6, 선택 중에만) |
| **잠깐 보이는 것** | 되돌리기·다시 시도 토스트(기존 토스트를 고침), 길게 누르기 첫 안내 토스트(**1차에서 거부한 "첫 사용 툴팁"과 같은 것**) |
| **늘어난 규칙** | "길게 누르면 옮기기", "부모 완료 = 하위 완료" (예산 2개 그대로) · 의도하지 않은 규칙 2개: **Memo는 Enter가 줄바꿈**(Task·Inbox는 Enter가 추가), **"다시 시도"가 두 곳에서 서로 다른 뜻**(알약 = 목록 저장, 입력창 실패 = + 다시 누르기) |

- 사용성 테스트의 심플함 인상: 7개 시나리오 중 6개가 +1~+2, PC만 0. 개선 전보다 **더 복잡해졌다는 시나리오는 하나도 없다.**
- 결론: 순감소는 확실하다(빠진 것 10종 이상, 늘어난 것 3~4개). 다만 **예산 밖으로 새어 들어온 것 3가지**(첫 안내 토스트, 의도하지 않은 규칙 2개)는 이번 회의에서 정리해야 한다. 아래 4절 참고.

## 1. 안건 C1 — 연타 시 다음 행까지 처리됨

**선택: ③ 둘 다. 단, ①이 주 해결책이고 ②는 보이지 않는 안전장치로만 쓴다.** · 점수 **0**(버그 수정, 요소·규칙 변화 없음)

- ① 사라진 자리를 약 300ms 비워 두었다가 접으면 "행이 빠져나가는 모습"이 보인다. 설명 없이도 이해되고, 두 번째 탭은 빈 자리에 떨어져 아무 일도 일어나지 않는다. 화면이 스스로 설명한다.
- ②는 그 자리·같은 손가락에 한정한다(QA R15처럼 전역으로 막으면 다른 행을 눌러도 무시된다). 사용자가 "눌렀는데 안 된다"고 느끼지 않도록 300ms를 넘기지 않는다.
- 같은 원리를 R9(연속 체크 중 앞 항목이 접히며 행이 밀리는 문제)에도 적용한다. "마지막으로 체크한 뒤 한꺼번에 접기"에 찬성한다. 규칙은 늘지 않고 손 밑이 덜 움직인다.

## 1-1. 안건 C2 — lab과 본 서비스의 저장소 분리
**찬성(이의 없음)** · 점수 0. 사용자 화면에는 변화가 없다. mock이 없으면 실행을 거부하는 안내도 lab 전용 한 줄이면 충분하다.

## 1-2. 안건 C3 — 엔지니어 수정에 붙이는 조건(반대가 아니라 조건)
| 항목 | 조건 |
|---|---|

| B-5 응답 유실 | 실제로 저장됐을 수 있으면 실패 토스트를 띄우지 않는다. 확인이 끝날 때까지 알약에 작게 "저장 중"을 유지(이미 있는 상태라 새 문구 없음) |
| 드래그 고스트 | 고스트를 손가락 위·왼쪽으로 비켜 화면 안에 두어 대상 행이 보이게 한다. "하위로 넣기" 문구는 **드래그하는 동안에만** 대상 행 안에 작게(늘 보이는 요소 아님) |
| Archive 복구 위치 | 토스트나 이동 안내를 더하지 말고 **원래 자리로 복구**해서 "어디 갔지?"를 없앤다 |
| 알약이 "남은 할 일"을 자름 | 알약이 뜰 때 "남은 n"이 줄바꿈되거나 짧아지게. 헤더 높이는 고정 |
| 메모 편집 중 × 20px | 보이는 크기는 그대로, 누르는 영역만 44px |

## 2. 안건 D1~D10

점수 = 심플함 변화(-2 더 복잡 ~ +2 더 단순)

| # | 선택 | 점수 | 근거 |
|---|---|---|---|

| D2 단일 완료·순서 되돌리기 | **① 토스트 없음 유지 + Cmd/Ctrl+Z가 체크·순서 변경도 무르게(PC, 보이지 않음)** | **0** | 체크는 가장 자주 하는 동작이다. 체크할 때마다 토스트가 뜨면 토스트가 소음이 되고, 정말 필요한 되돌리기·실패 토스트를 읽지 않게 된다. 800ms 머무름 동안 다시 누르기와 체크 해제가 이미 되돌리기 역할을 한다.<br>순서 변경은 결과가 제자리에 보이고, B-3(제자리 놓기 = 취소)를 고치면 불안이 사라진다. ②·③ 거부. |

| D8 길게 누르기 첫 안내 토스트 | **③ 없앰** | **+1** | 1차에서 "첫 사용 툴팁"을 거부했는데 같은 것이 들어왔다. 사용자는 tako를 만든 1명이다. 그리고 1차에서 정한 대체 경로(PC hover 핸들, 시트의 "보관함으로")가 이미 있다.<br>② "드래그 실패 감지"는 언제 뜰지 알 수 없는 토스트와 숨은 판정 로직을 더한다. 거부한다. |
| D9 영어 혼용 | **① 1차 결정 유지** | **0** | 사용성 테스터의 지적은 1차에서 이미 검토한 내용이다. 실제 사용자가 새로 불편을 말한 근거가 없다. 익숙한 이름을 바꾸면 다시 익히는 비용이 생긴다.<br>D5에서 🥚를 "Inbox"로 바꾸면 탭 이름과 보관함 표기가 맞춰진다. |
| D10 꼭 필요한 것(최대 2개) | 아래 2개 | **+1, +1** | 둘 다 요소를 늘리지 않고, 1차에서 **의도치 않게 생긴 규칙을 없앤다** |

### D10 제안 (요소 0개, 규칙 −2개)
1. **"다시 시도"를 한 가지 뜻으로** — 모든 파일(Task·Inbox·Memo·Archive) 저장 실패를 헤더 알약 하나에 연결한다. 입력창 추가 실패도 C3-R1처럼 행을 남기고 알약으로 재시도한다. "실패하면 빨간 알약을 누른다" 하나만 알면 된다(사용성 6번 지적 2건 해결).
2. **편집 시트를 말 그대로 동작하게** — ① "취소" = 이 시트에서 한 일 **전부** 무르기(시트에서 추가한 하위 할 일 포함, B-7). ② 모바일에서는 시트를 열 때 내용칸에 자동 포커스하지 않는다(우선순위만 바꿀 때 키보드가 시트를 가리지 않게). PC는 지금처럼 자동 포커스. 시트 안에 버튼은 늘리지 않는다.

**합계: +6 / 11건, 늘 보이는 새 요소 0개, 새 규칙 0개(오히려 −2).**

| 4 | **시트 "취소"가 하위 추가를 무르지 않음** | 사용성 1번, B-7 | 취소 = 전부 무르기(D10-2) | 말과 동작 불일치 해소 |
| 5 | **PC hover ×가 빨간 채움 원(삭제처럼 보임)** | 사용성 7번: 실제로는 보관 | 모바일 시트·Inbox와 같은 📥(또는 회색 테두리 아이콘)로. 빨강은 영구 삭제에만 | 같은 모양 = 같은 결과 |
| 6 | **Archive 행의 하위 개수 "+1"** | 1차 예산에 없던 상시 요소 | **유지는 허용하되 예산 1개로 셈하지 않는 조건**: 날짜와 같은 회색 메타 줄 안에 붙인다(새 줄·새 배지 금지). 따로 배지가 되면 제거 | 상시 요소 증가 방지 |
| 7 | **"완료"가 두 가지 모습으로 보임**(미완료 부모 아래 하위 완료는 줄 그은 채, 나머지는 접힘) | 사용성 2번 | 되돌리지 않음. "하위는 부모를 따라간다"로 이해 가능하고, 바꾸면 새 규칙이 생긴다. 기록만 남긴다 | — |

참고: "완료 n개" 펼침 상태를 기억하는 것은 1차에서 내가 "기억하지 않기"를 제안했던 부분이다. 사용성 테스트에서 좋은 점으로 꼽혀 **그대로 둔다**(사용자 경험이 근거보다 우선).

## 5. 남은 예산 사용 계획

- **늘 보이는 요소 1개: 쓰지 않는다.** 후보였던 `2/5`는 근거가 없어 넣지 않는다. 다음 사용성 테스트나 실사용에서 "필요하다"는 신호가 나오면 그때 쓴다.
- **새 규칙 0개: 지킨다.** 이번 결정은 오히려 의도치 않게 생긴 규칙 2개를 없앤다(다시 시도 통일, 메모 Enter 표시).
- 9점으로 가는 길은 **기능 추가가 아니라 오조작 방지(C1·B-3·B-2)와 말과 동작 맞추기(D10)** 라고 본다. 사용성 감점 요인도 거의 다 여기에 있었다.
