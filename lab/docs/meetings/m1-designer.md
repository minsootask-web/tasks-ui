## 1. 안건 B 결정

### B1. 확인창 → **② 확인창 없애고 공용 "되돌리기" 토스트**
- 근거: 보관·분류·완료·메모 삭제는 원래 되돌릴 수 있어서 확인창이 "확인" 반사 클릭만 늘림(리서치 공통 가이드라인). 지금도 일괄 보관에만 되돌리기가 있어 규칙이 제각각(감사 C6).
- 근거: 토스트 1개로 B1·B9·B11·A1을 모두 처리 → 새 요소는 사실상 0개.
- 스펙
  - 위치: 하단 입력창 바로 위 가운데(현행 `bottom: safe + 90px` 유지). 입력창이 없는 화면은 `safe + 24px`.
  - 모양: 현행 알약형 유지(배경 `--text`, 글자 `--bg`, 13px). 오른쪽 "되돌리기" 버튼은 높이 32px·좌우 12px 여백, 터치 영역은 위아래로 넓혀 44px.
  - 시간: 되돌리기가 있는 토스트 **5초**, 오류 토스트 **6초**, 그 밖 정보 토스트 2.5초. 손가락·마우스가 올라가 있는 동안은 시간 멈춤.
  - 한 번에 하나만. 새 토스트가 오면 이전 것은 그 자리에서 확정되고 교체(쌓지 않음).
  - PC: `Cmd/Ctrl+Z` = 마지막 토스트의 되돌리기.
  - 문구(쉬운 말, "~했어요" 통일):
    - 보관: `보관함으로 옮겼어요` · `되돌리기`
    - 여러 개 보관: `3개를 보관함으로 옮겼어요` · `되돌리기`
    - Inbox 분류: `🍅 High로 보냈어요` · `되돌리기`
    - 메모 삭제: `메모를 지웠어요` · `되돌리기`
  - 확인창은 **보관함의 영구 삭제 하나만** 남김. 문구: 제목 `완전히 지울까요?` / 본문 `지우면 다시 살릴 수 없어요.` / 버튼 `취소`·`지우기`(빨강).

### B2. 모바일 행의 ⋮⋮·× → **④ 둘 다 편집 시트 안으로 (+ 드래그는 길게 누르기)**
- 근거: 375px에서 글 폭이 179px뿐이고 회색 기호 기둥이 생김(감사 B2). 두 버튼을 빼면 글 폭이 약 243px로 늘어 줄바꿈이 크게 줄어듦.
- 근거: 스와이프(③)는 안 보이는 동작이라 외워야 하고, 오조작 위험이 실재함(TickTick 공식 안내). 시트는 이미 있는 화면이라 새 개념이 아님.
- 스펙
  - 모바일(`hover: none`): 행에는 체크·글·펼침 화살표만. ⋮⋮·× 없음.
  - PC: 현행처럼 마우스를 올렸을 때만 ⋮⋮·× 보임(유지).
  - 편집 시트 맨 아래 왼쪽에 글자 버튼 `보관함으로`(회색 글자, 높이 44px). 누르면 시트가 닫히고 B1 토스트. 오른쪽은 현행 `취소`·`저장`.
  - 드래그: 행을 400ms 길게 누르면 행이 살짝 떠오름(크기 1.02배, 그림자 `--shadow`, 배경 `--surface`) + 진동 10ms. 누르는 동안 0.98배로 살짝 눌리는 예고 효과.
  - 길게 누르기 첫 1회: 토스트 `길게 눌러 순서를 바꿀 수 있어요` 1번만(이후 안 띄움, 기기에 기억).

### B3. 완료 항목 → **② 섹션 아래 "완료 n개" 접기 행 (기본 접힘, ⇅ 제거)**
- 근거: 줄 그은 항목이 계속 남아 남은 일이 묻힘. ⇅는 뜻이 잘 안 보이고 상태도 기억 못 함(감사 C5). 접기 행은 Google Tasks·미리알림으로 익숙한 모양.
- 근거: 헤더 아이콘 1개(⇅)가 줄어 오히려 단순해짐.
- 스펙
  - 체크 → 튀는 체크 300ms + 취소선 → **800ms 머무름** → 높이·투명도를 200ms에 줄이며 접기 행 속으로 들어감. 머무는 동안 다시 누르면 취소(아무 일도 없던 것처럼).
  - 접기 행: 섹션 마지막 행 아래, 높이 36px, 왼쪽 들여쓰기는 체크박스 줄에 맞춤. 글자 13px `--muted` 색: `완료 4개 ›`. 펼치면 `완료 4개 ⌄`.
  - 새로 완료되면 숫자가 120ms 동안 살짝 커졌다 돌아옴(1.15배) → "여기로 들어갔다"는 신호.
  - 펼침 상태는 섹션별로 기기에 기억(실패해도 기본 접힘).
  - 완료가 0개면 접기 행 자체를 숨김.
  - 완료 하나 체크에는 토스트를 띄우지 않음(가장 잦은 동작이라 소음이 됨). 800ms 머무름이 실수 복구 시간 역할.
  - "완료 항목 보관"은 ⋯ 메뉴에 그대로.

### B4. 탭 이름·언어 → **③ 탭은 영어 유지 + 나머지 문구는 쉬운 한국어로 정리**
- 근거: Task/Inbox/Memo/Archive는 짧아서 375px에 4개가 넉넉히 들어가고, 이미 손에 익은 tako의 얼굴. "수집함"은 오히려 낯섦.
- 근거: 문제는 탭이 아니라 "실패: conflict", "PUT 500" 같은 개발 용어와 영어 툴팁(감사 C3).
- 스펙
  - 탭·우선순위 이름(High/Medium/Low)만 영어. 섹션 제목 `🍅 HIGH`(11px 대문자) → `🍅 High`(13px, 굵게 600)로 읽기 쉽게.
  - 오류·안내·툴팁·버튼은 전부 한국어 "~했어요/~할까요?" 말투. 개발 용어(PUT, 500, conflict, sync) 화면 노출 금지.
  - 대표 문구: `저장하지 못했어요` · `다시 시도` / `인터넷 연결을 확인해 주세요` / `다른 기기에서 바뀐 내용을 불러왔어요`.

### B5. 추가 방식 → **② 하단 입력창을 Inbox·Memo에도, Archive는 추가 없음**
- 근거: 엄지가 닿는 아래쪽, 같은 자리에서 늘 추가 → 탭마다 다른 방법을 외울 필요 없음(감사 C1). FAB가 선택 바에 가려지는 문제(감사 B5)도 같이 사라짐.
- 근거: Archive FAB가 Inbox에 추가되는 어긋남과 배지 버그(A9)가 원인째 없어짐.
- 스펙
  - Task: 현행 그대로(왼쪽 우선순위 버튼 + 입력 + 빨간 + 버튼).
  - Inbox: 왼쪽 우선순위 버튼 자리 없음. 안내 글 `Inbox에 적어 두기`.
  - Memo: 안내 글 `메모 남기기`. Enter = 추가, `Shift+Enter`(모바일은 줄바꿈 키) = 줄바꿈, 입력창은 최대 4줄까지 늘어남. 추가된 메모는 보드 맨 앞(1열 맨 위)에 노란 카드로 200ms 페이드인.
  - Archive: 입력창 없음, 본문 아래 여백도 입력창 높이만큼 줄임.
  - 모든 입력창: 추가 후 글만 비우고 포커스 유지(연속 입력), 모바일 키보드도 닫지 않음.

### B6. 인라인 우선순위 문법 → **② 안 넣는다 (지금은)**
- 근거: 보이지 않는 규칙이라 외워야 함. "급함!!"처럼 평소 쓰는 느낌표가 우선순위로 바뀌는 오인식 위험.
- 근거: 왼쪽 🍋 버튼 한 번이면 되고, 봇 문법과도 아직 안 맞춰져 있음. 쓰는 사람이 원하면 2차에서 다시 검토(양보 가능 항목).
- 대신: 왼쪽 우선순위 버튼에 `title`/`aria-label`을 `우선순위: 🍋 Medium (누르면 바뀜)`으로 쉽게.

### B7. 하위 할 일 만들기 → **② 편집 시트에 "하위 할 일 추가"**
- 근거: 지금은 드래그로만 만들 수 있어 아는 사람만 씀(감사 C8). 시트는 이미 있는 화면이고 버튼 1개만 늘어남.
- 근거: 들여쓰기 문법(③)은 B6과 같은 이유로 보류.
- 스펙
  - 상위 항목의 시트에서만 보임(하위는 1단계까지만). 글 입력란 아래에 글자 버튼 `+ 하위 할 일 추가`(13px `--muted`, 높이 44px).
  - 누르면 그 자리에 한 줄 입력란이 열리고 바로 포커스. Enter = 추가하고 다음 줄 입력란 유지, 빈 채로 Enter 또는 바깥 누르면 닫힘.
  - 시트 위쪽에 이미 있는 하위 할 일 목록을 13px로 보여주고(최대 5개, 넘치면 `외 3개`), 시트를 닫으면 부모가 펼쳐진 상태로 새 하위 항목이 보임.
  - 드래그로 넣기는 그대로 두되, 하위로 들어가는 영역을 행 가운데 50% → **오른쪽으로 24px 이상 끌었을 때**로 좁힘(감사 B7).

### B8. 저장 상태 표시 → **② 평소엔 숨기고, 저장 중엔 작게, 실패 때만 강조 + 다시 시도**
- 근거: 늘 보이는 "동기화됨"은 정보가 없고, 지금은 틀리기까지 함(감사 A7). 문제가 있을 때만 보이면 눈에 띄는 힘이 커짐.
- 근거: 헤더 메타가 두 줄 ↔ 한 줄로 바뀌며 화면이 밀리는 문제도 같이 해결.
- 스펙
  - 자리: 헤더 오른쪽(⋯ 버튼 왼쪽) 고정 칸. 평소엔 비어 있음 → 화면이 밀리지 않게 자리만 잡음.
  - 저장 중: 0.6초 넘게 걸릴 때만 6px 주황 점(`--med`, 깜빡임 1s) + 11px `저장 중`. 빠르게 끝나면 아예 안 보임.
  - 저장됨: 표시 없이 사라짐(200ms 페이드).
  - 실패: 빨간 알약(배경 `--accent-soft`, 글자 진한 빨강 `--accent-strong`, 12px 600) `저장 안 됨 · 다시 시도`. 누르면 바로 다시 저장. 성공할 때까지 계속 보임(다른 탭으로 가도 유지).
  - 인터넷 끊김: 회색 알약 `오프라인`. 다시 연결되면 자동 저장 후 사라짐.
  - 저장 안 된 변경이 있을 때 창 닫기 → 브라우저 기본 경고(`beforeunload`).

### B9. 낙관적 업데이트 범위 → **② 전부 즉시 반영 + 실패 시 되돌림**
- 근거: 이동·보관은 1초 넘게 아무 반응이 없어 "눌렸나?" 하고 다시 누르게 됨 → 연타 오류(감사 A8, E1). 즉시 반영하면 연타 자체가 사라짐.
- 근거: 실패 때 되돌리는 모양을 B1 토스트와 같게 하면 배울 것이 없음.
- 스펙
  - 누르는 즉시 결과대로 화면을 바꿈(행 사라짐 200ms, 새 행 200ms 페이드인). 흐리게 하는 "처리 중" 모양은 쓰지 않음(평소엔 깔끔하게).
  - 실패하면: 항목이 원래 자리로 돌아오고 그 행 배경을 `--accent-soft`로 600ms 깜빡여 "여기 돌아왔어요"를 알림 + 오류 토스트 `옮기지 못했어요 · 다시 시도`(6초).
  - 추가 실패는 A1 규칙(아래 2절) 우선: 행을 거두고 **입력한 글을 입력창에 되돌림**.
  - 처리 중인 같은 항목을 또 누르면 무시(두 번 보내지 않음).

### B10. 우선순위 표기 통일 → **찬성, 🍅🍋🥝 + High/Medium/Low 한 쌍으로**
- 근거: 같은 개념이 네 가지 모양(감사 C2). 과일 아이콘은 tako 정체성의 핵심이라 여기로 모으는 게 맞음.
- 스펙
  - 섹션 제목: `🍅 High` `🍋 Medium` `🥝 Low`.
  - Inbox 행 버튼: H/M/L 글자 → 🍅🍋🥝 이모지 버튼 3개(보이는 크기 28px, 터치 44px, 이모지 16px). 접근성 이름 `High로 보내기` 등.
  - 시트 우선순위 칸: 색 점 대신 `🍅 High` 알약 3개.
  - 토스트: `🍅 High에 추가했어요`(옛 🔥🟡🟢 모두 제거).
  - 보관함 배지: 같은 3개(🥚 등 어긋난 아이콘 정리).
  - 색: 이모지로 충분하므로 체크박스 테두리 색 입히기(리서치 #9)는 안 함 — 색이 늘어나면 차분함이 깨짐.

### B11. 부모 완료 시 하위도 완료 → **① 넣는다**
- 근거: 미리알림·Todoist와 같은 예상 가능한 규칙. 부모만 완료하고 하위가 남는 어정쩡한 상태가 없어짐.
- 근거: B3 접기 행과 맞물려 부모와 하위가 함께 깔끔히 정리됨.
- 스펙
  - 미완료 하위가 있는 부모를 체크 → 하위 체크박스도 위에서부터 40ms 간격으로 차례로 튀며 체크(최대 5개까지만 차례 효과, 나머지는 동시에).

### B12. 탭 위치 → **① 상단 유지 (높이만 44px로)**
- 근거: 하단에는 이미 입력창과 토스트가 있어 탭바까지 오면 812px 화면에서 아래 약 130px가 고정 영역이 됨. 목록이 좁아지고 엄지 영역이 붐빔.

### B13. Memo 모바일 스크롤 → **① 길게 눌러 드래그**
- 근거: B2와 같은 손동작으로 맞추면 "옮기려면 길게"라는 규칙 하나만 기억하면 됨. 핸들 영역(②)은 노란 카드에 회색 요소를 하나 더 얹음.
- 스펙

  - 8px 이상 먼저 움직이면 스크롤로 판단하고 드래그 안 함.
  - 메모 ×는 카드를 눌러 편집 중일 때만 오른쪽 위에 보임(터치 44px, 글과 겹치지 않게 카드 오른쪽 여백 28px 확보). 지우면 B1 토스트.

## 2. 안건 A — 실패했을 때 사용자에게 어떻게 보여야 하나

원칙 세 가지: **① 쓴 글은 절대 사라지지 않는다 ② 한 항목은 언제나 한 곳에만 보인다 ③ 실패는 해결될 때까지 보이고, 쉬운 말과 "다시 시도" 하나로 끝난다.**

| 감사 | 사용자에게 보이는 모습 |
|---|---|
| A1 입력창 추가 실패 | 새 행이 200ms에 걷히고, 쓴 글이 입력창에 그대로 돌아옴(커서는 글 끝, 우선순위 버튼도 그때 값). 토스트 `저장하지 못했어요` · `다시 시도`(6초). 다시 시도 = 같은 글 그대로 다시 추가. |

## 3. 안건에 없지만 꼭 필요한 것 (3개)

1. **모션·피드백 기준값을 한 곳에 (맨 위 "공통 기준값" 표)**
   지금은 0.12s/0.15s/0.18s/0.3s가 곳곳에 흩어져 있음. CSS 변수(`--dur-fast: 120ms`, `--dur: 200ms`, `--ease`)로 묶고 `prefers-reduced-motion`을 함께 처리해야, 이번에 늘어나는 접힘·되돌림·길게 누르기 효과가 같은 리듬으로 느껴짐.
2. **공용 토스트 규칙(한 개만, 교체, 되돌리기는 마지막 것만, `Cmd+Z`, `role=status`)**
   B1·B9·B11·A1·A4가 모두 이 토스트 하나에 기대므로 컴포넌트를 먼저 만들고 나머지가 그걸 쓰게 해야 함. 따로따로 만들면 시간·위치·문구가 또 갈라짐.
3. **새 항목이 화면 밖에 추가될 때 "어디 갔는지" 보여주기 (감사 C10)**
   🥝 Low로 추가하면 화면 밖 아래에 들어가 성공했는지 모름. 화면 밖이면 그 행으로 300ms 부드럽게 스크롤 + 행 배경 `--accent-soft` 600ms 깜빡임. 화면 안이면 깜빡임만. 토스트를 띄우지 않아 조용함.
