## 안건 C1. 연타가 다음 행에 들어감 → **③ 둘 다 (자리 잠깐 비워 두기 + 그 자리 탭 무시)**

- 근거: 0.1초 간격 더블탭은 눈으로 보고 멈출 수 없는 속도라, 화면만 바꾸면(①) 접히는 200ms 동안 올라오는 행에 여전히 맞을 수 있음. 반대로 탭 무시만(②) 하면 "눌렀는데 반응이 없다"로 느껴짐. 둘을 겹쳐야 보는 것과 실제가 맞음.
- 근거: Task 행은 이미 `.leaving`(투명 → 높이 접기)이 있음. Inbox·Archive만 즉시 사라져서 생긴 문제라, 같은 모션을 쓰면 새 규칙이 아님.
- 스펙
  1. 행 처리(분류·보관·복구·영구 삭제) 순간: 내용만 `--dur-fast`(120ms)에 투명해짐. **행 높이는 300ms 동안 그대로 유지**(빈 자리).
  2. 그 뒤 `--dur`(200ms)에 높이 0으로 접힘 → 총 500ms.
  3. 탭 무시 범위: 이 500ms + 여유 150ms(= **650ms**) 동안, **사라지는 행이 있던 자리의 화면 영역**에 들어온 탭만 무시. 다른 행·다른 버튼은 바로 눌림(R15처럼 전역으로 막지 않음).
  4. 무시된 탭에는 아무 표시도 하지 않음(흔들림·소리 없음).
  5. 연속 체크(Task)도 같은 원리: 체크가 들어올 때마다 모든 머무름 타이머를 800ms로 다시 미루고, **마지막 체크 뒤 한꺼번에** 접기(R9). 접히는 200ms 동안 위 3번 규칙 적용.
  6. 모션 줄이기 설정: 빈 자리 유지는 그대로(안전 장치), 접기만 120ms.

## C3. 엔지니어 판단 항목 → **반대 없음.** 디자인 쪽 확인만
- R4(붙여넣은 줄바꿈): Task·Inbox는 **여러 항목으로 나눠 넣기**를 선호. "쓴 글은 사라지지 않는다"에 더 맞고, 붙여넣은 목록이 한 번에 들어가는 게 자연스러움. 화면 밖이면 첫 항목으로 스크롤 + 넣은 행 전부 깜빡임.
- R1(입력 실패 글 여러 개): 되돌아온 글이 여럿이면 입력창에 **줄바꿈으로 합쳐** 넣고(위 R4 규칙으로 다시 나뉘어 들어감) 토스트는 `3개를 저장하지 못했어요 · 다시 시도`.
- B-5(응답 유실): 저장 여부를 모를 때 문구는 `저장됐는지 확인하고 있어요`(정보 토스트 2.5초, 버튼 없음) → 확인되면 조용히 사라짐, 실패로 확정될 때만 `저장하지 못했어요 · 다시 시도`.
- B-2(선택 모드 행 높이): 선택 모드에서 행 버튼은 `display:none` 대신 `visibility:hidden`으로 숨겨 **높이를 그대로** 유지.
- B-3(제자리 놓기): 처음 자리 ±절반 행 안에서 놓으면 **취소**. 고스트가 원래 자리로 `--dur`(200ms)에 미끄러져 돌아가는 모션으로 "취소됐다"를 보여줌.

## 안건 D

### D1. 입력창 우선순위 순환 순서 → **① 🍋 → 🍅 → 🥝**
- 근거: 기본값이 🍋 Medium이라 **한 번 누르면 가장 자주 원하는 🍅 High**, 두 번이면 🥝 Low. 사용성 테스트에서 "High로 가려면 2번"이 가장 큰 불만이었음.
- 근거: 팝오버(②)는 누를 횟수가 같거나 많고(열기 + 고르기 = 2번), 입력창 위에 새 층이 생김. 규칙 예산 0에도 걸림.
- 스펙
  - 순서: 🍋 Medium → 🍅 High → 🥝 Low → 🍋 …
  - 누를 때 아이콘이 0.9배로 눌렸다가(현행 `:active`) 새 이모지가 120ms 동안 1.15배 → 1배로 튐(완료 개수 `done-bump`와 같은 모션 재사용).
  - `aria-label` / `title`: `우선순위 🍋 Medium · 누르면 🍅 High` (다음 값을 미리 알려줌).
  - 마지막으로 고른 값은 다음 입력에도 그대로 둠(현행). 별도 안내 없음.

### D2. 단일 완료·순서 변경의 되돌리기 → **① 토스트 없음 유지 + Cmd/Ctrl+Z는 모두 지원**
- 근거: 완료는 가장 잦은 동작이라 토스트를 붙이면 매번 화면 아래를 가림(사용성 "토스트가 행을 가림" 지적). 1차 원칙 4 "토스트는 되돌리기·다시 시도만, 소음 금지"와도 맞음.
- 근거: "어디 갔지?" 불안은 이미 있는 800ms 머무름 + `완료 n개` 숫자 튐으로 대부분 해결. 순서 변경은 일부러 끄는 동작이고, B-3(제자리 놓기 = 취소)가 고쳐지면 실수 이동이 거의 사라짐.
- 스펙
  - PC: `Cmd/Ctrl+Z`가 토스트 유무와 상관없이 **마지막 1개 동작**(체크·체크 해제·순서 변경·우선순위 변경·추가)을 무름. 무를 때만 그 행을 600ms 깜빡임 + 화면 밖이면 스크롤. 토스트는 띄우지 않음.
  - 입력창·시트 입력란에 포커스가 있을 땐 브라우저 기본 되돌리기(글자 되돌리기) 그대로.
  - 모바일: 추가 장치 없음. 실수 완료는 0.8초 안에 다시 누르거나 `완료 n개`를 펼쳐 해제.
  - 체크 해제하면 원래 자리로 돌아가는 현행 동작 유지(돌아갈 때 600ms 깜빡임만 추가 — 새 요소 아님).

### D3. PC 입력창 포커스 단축키 → **① `/`와 `N` 둘 다**
- 근거: PC 시나리오가 0점이었던 가장 큰 이유가 "입력창까지 Tab 80번". 화면에 아무것도 늘지 않음.
- 스펙
  - 키 판정은 `e.code`(`Slash`, `KeyN`)로 → **한글 입력 상태(ㅜ)에서도 동작**.
  - 입력란·시트·메뉴가 열려 있을 때, `Cmd/Ctrl/Alt`와 함께 눌렸을 때는 무시.
  - 누르면 현재 탭의 입력창에 포커스(Archive에선 무시), 입력창 테두리가 빨강(현행 `:focus-within`)으로 바뀌는 것이 피드백.
  - `Esc`: 입력창에서 포커스를 빼고 마지막으로 보던 행으로 돌아감.
  - PC(`hover: hover`)에서만 안내 글에 힌트: `할 일 입력…  /` → 실제 문구 `할 일 입력 (/ 키)`. Inbox `Inbox에 적어 두기 (/ 키)`, Memo `메모 남기기 (/ 키)`. 모바일 문구는 그대로.

### D4. Inbox 항목 글 고치기 → **① 글자를 누르면 시트로 편집**
- 근거: Task와 똑같이 "글 누르면 편집"이 되어 **규칙이 오히려 하나로 합쳐짐**(지금은 Task=편집, Inbox=선택으로 달라서 헷갈림). 새 규칙 아님.
- 근거: 선택은 이미 있는 왼쪽 체크박스(44px)로 충분. 사용성 B-2(선택하다 빗나감)도 누르는 곳이 체크박스 하나로 좁아져 줄어듦.
- 스펙
  - 글 누름 → 기존 편집 시트 재사용. 제목 `Inbox 항목 고치기`, 입력란 1개 + `취소`·`저장` + 왼쪽 아래 `보관함으로`. 하위 할 일·우선순위 칸은 없음(시트 안 새 요소 0).
  - 선택 모드일 때만 글 누름 = 선택(지금처럼). 선택 모드 밖에선 편집.
  - 터치 기기에선 시트를 열어도 키보드를 자동으로 올리지 않음(D10-1과 같은 규칙), PC는 자동 포커스.

### D5. 보관함 🥚(Inbox 출처) → **① 🥚 대신 작은 글자 `Inbox`**
- 근거: 🍅🍋🥝 옆에 🥚가 있으면 "네 번째 우선순위"로 읽힘. 과일 아이콘은 우선순위 전용으로 지키는 게 tako 정체성에 맞음.
- 근거: 툴팁(②)은 터치 기기에서 볼 수 없음.
- 스펙: 이모지 자리(같은 폭 맞춤 필요 없음)에 알약 배지 `Inbox` — 11px, 굵기 600, 글자 `--muted`, 배경 `--surface-2`, 좌우 6px·높이 18px, 모서리 999px. 접근성 이름 `Inbox에서 보관`. 탭 이름과 같은 말이라 따로 배울 것 없음.

### D6. `!!!` 문법 → **③ 이번 범위에서 폐기**
- 근거: 새 규칙 예산이 0. 실데이터에 "짜기!!!!!!!!" 같은 느낌표가 있어 오인식 위험도 그대로.
- 근거: D1로 High가 1번 누름이 되어 문법의 이득(키보드에서 손 안 떼기)이 더 작아짐. PC는 D3 + D1이면 충분. 다시 꺼내려면 사용 데이터로 근거를 가져오는 걸 조건으로.

### D7. 접힌 부모 옆 `2/5` → **① 넣는다, 단 이미 있는 하위 개수 배지의 내용만 바꿔서 (예산 사용 0)**
- 근거: 지금도 접힌 부모 옆에 회색 배지(`.child-count`, 숨겨진 하위 개수 `3`)가 있음. 숫자를 `완료/전체`로 바꾸는 것이라 **늘 보이는 새 요소가 아님** → 남은 예산 1개는 아껴 둠.
- 근거: `3`만으로는 "3개 남음인지 3개 있음인지" 모호함. `2/5`는 더 많은 정보를 같은 자리에서 줌.
- 스펙
  - 접혔을 때만 보임(현행 그대로). 내용 `2/5`, 11px 600, `font-variant-numeric: tabular-nums`, 색 `--muted`, 배경 `--surface-2`(현행).
  - 전부 완료(`5/5`)면 배지 글자색만 `--low`(초록)로. 막대·퍼센트 없음.
  - 하위 하나를 완료할 때 숫자가 바뀌면 `done-bump`(120ms 1.15배) 재사용.
  - `title`/접근성 이름: `하위 할 일 5개 중 2개 완료`.

### D8. 길게 누르기 첫 안내 토스트 → **③ 없앤다**
- 근거: 1차 원칙 4 "토스트는 되돌리기·다시 시도 두 용도만"에 어긋나는 유일한 토스트. 그리고 첫 화면에 바로 뜨면 아직 옮길 생각도 없는데 정보가 먼저 옴.
- 근거: ②(실패 감지)는 "핸들 찾다 실패"를 판정할 신호가 애매하고, 조건 하나가 사실상 새 규칙.
- 대신(새 요소 없이 발견성 확보): 누르고 있는 동안 행이 0.98배로 눌리는 **예고 모션**을 조금 더 분명하게 — 200ms 지난 시점부터 배경을 `--hover`로 서서히 채워 400ms에 꽉 차게(누르면 뭔가 차오른다는 느낌). 드래그 시작 순간 진동 10ms(현행).

### D9. 탭·섹션 이름 영어 혼용 → **① 1차 결정 유지**
- 근거: 혼용 지적은 "규칙 없는 섞임" 때문이었고, 지금은 "**이름(탭·우선순위)만 영어, 문장은 전부 한국어**"라는 선이 분명함. Task/Inbox/Memo/Archive·High/Medium/Low는 짧고, 375px에 4탭이 여유 있게 들어감.
- 근거: 이번 회의에서 이름을 바꾸면 봇 메시지·사용자 습관·문서까지 함께 흔들림. 9점에 필요한 건 이름보다 오조작·키보드 쪽.
- 확인 요청(새 작업 아님): 남은 영어 **문장**(툴팁·접근성 이름·오류)이 0개인지 마지막 점검. 예: `title="medium"` → `우선순위 🍋 Medium`.

### D10. 완성도 9점을 위해 꼭 필요한 것 (2개)

**D10-1. 편집 시트의 "취소" 뜻 맞추기 + 터치 기기 자동 키보드 끄기**
- 근거: 사용성 B-7(취소했는데 하위가 저장됨)과 "우선순위만 바꾸려는데 키보드가 시트를 가림"은 매일 쓰는 시트에서 신뢰를 깎음.
- 스펙
  - 하위 할 일 추가는 지금처럼 Enter마다 바로 저장(쓴 글 보존 원칙). 대신 **시트에서 하위를 하나라도 추가했으면 왼쪽 버튼 문구를 `취소` → `닫기`로** 바꿈. `닫기`는 본문 글·우선순위 수정만 버리고, 추가한 하위는 남김(이미 화면에 보이므로 놀라지 않음).
  - 터치 기기(`hover: none`): 시트를 열면 **아무 칸에도 자동 포커스하지 않음**. 글 칸을 누르면 그때 키보드. PC는 현행처럼 글 칸 자동 포커스.
  - 시트 안 하위 목록 줄을 누르면 그 줄이 한 줄 입력란으로 바뀌어 고칠 수 있고, 글을 다 지우고 Enter = 그 하위를 보관함으로(되돌리기 토스트). 버튼 추가 없음.

**D10-2. PC 키보드 동선 마무리 (포커스가 길을 잃지 않게)**
- 근거: PC 시나리오 0점의 남은 원인은 "시트 닫으면 포커스가 맨 앞으로 감(B-4/R12)", "완료하면 그 항목이 접혀 다음으로 가기 어려움".
- 스펙
  - 시트를 닫으면(저장·취소·Esc 모두) **그 할 일 글**로 포커스 복귀. 행이 다시 그려졌으면 같은 항목을 찾아 복귀, 없어졌으면(보관) 바로 아래 행.
  - Space로 체크한 항목이 800ms 뒤 접히면 포커스를 **다음 미완료 항목의 체크박스**로 옮김(없으면 위 항목, 섹션이 비면 `완료 n개` 행).
  - 포커스 링은 모든 곳에서 2px `--accent`, `outline-offset: 2px`로 통일.
  - 핸들 ↑↓ 이동은 이번에도 보류(규칙 예산 0, `Alt+↑↓`는 다음 회차).

## 지금 lab의 시각·모션 다듬을 점 (5개, 새 요소 없음)

1. **드래그 고스트가 대상 행을 가리고 오른쪽으로 삐져나감**
   - 터치 드래그일 때 고스트를 손가락보다 **위로 28px** 띄워(손가락 바로 아래 행이 보이게) 그리고 폭을 목록 카드 폭에 맞춰 `max-width`로 묶어 화면 밖으로 안 나가게. 고스트 크기 1.02배, 불투명도 .92 → .88.
   - "하위로 넣기" 상태가 되면 **고스트 자체가 오른쪽으로 24px 들여 써지며**(`--dur-fast`) 대상 행 점선 테두리를 실선 2px `--accent`로 바꿈 → 글 없이 "이 아래로 들어간다"가 보임.
2. **PC hover ×가 빨간 채움 원이라 "삭제"처럼 보임**
   - Task·Inbox의 ×(실제로는 보관)는 hover 배경을 `--surface-2` + 글자 `--text`로(일반 버튼과 같게), 툴팁 `보관함으로`. **빨간 채움(`.row-btn.danger:hover`)은 보관함의 🗑 영구 삭제에만** 남김. 위험도와 색이 맞게.
3. **사라지는 모션이 화면마다 다름**
   - Task는 투명 → 접기, Inbox·Archive는 즉시 사라짐, 메모는 그냥 빠짐. 모두 C1 스펙(투명 120ms → 자리 300ms 유지 → 접기 200ms)으로 통일. 메모는 높이 대신 `scale(.96)` + 투명 120ms 뒤 빠짐.
4. **메모 편집 중 ×가 20px로 작고 노란 바탕에 묻힘**
   - 보이는 크기 20 → **24px**, 글자 14px, 바탕 `memo-fg 12%` → `16%`. 누르는 영역은 지금처럼 `::before`로 넓히되 `inset: -10px`(44px). 위치는 오른쪽 위 6px 안쪽.
5. **저장 안 됨 알약이 뜨면 `남은 할 일 n`이 `남은 …`으로 잘림**
   - 헤더 메타 줄에서 `남은 할 일 n`은 `flex-shrink: 0; white-space: nowrap`로 절대 안 줄게 하고, 줄어드는 쪽은 날짜 글자(말줄임). 375px에서 알약 + 숫자가 함께 보이는지 확인.
