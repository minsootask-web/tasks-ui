## 0. 거르는 기준 세 가지

모든 제안을 아래 세 질문으로 걸렀다.

1. **화면 요소**: 늘 보이는 요소가 하나라도 늘어나는가? (시트·메뉴 안은 반만 센다)
2. **외울 규칙**: 사용자가 새로 알아야 하는 규칙·문법·제스처가 생기는가?
3. **실제 매일 겪는 문제인가**: 사용 데이터(High 20개 이상, 회의록 같은 긴 하위 할 일, 정리 안 된 완료 항목, 메모 14개, 보관함 123개)에 근거가 있는가?

판정 원칙: 무언가를 **빼서** 마찰이 줄면 적극 찬성. 무언가를 **더해서** 해결하려 하면, 대신 빠지는 요소가 있을 때만 찬성.

### 숨겨진 제스처를 어떻게 볼까 (B2·B13 공통)
- **불리한 점**: 발견성이 낮다. 처음 쓰는 사람은 모른다. 길게 누르기는 스크롤·탭(=편집)과 헷갈릴 수 있다.
- **유리한 점**: 모바일 행마다 ⋮⋮·×가 있어 글 폭이 375px 중 179px뿐이다(감사 B2). High 20개 이상인 실제 데이터에서는 이 "회색 기둥"이 화면을 가장 지저분하게 만든다.
- **판단**: 사용자는 1명이고 tako를 직접 만든 사람이라 발견성 비용이 거의 없다. 대신 아래 세 조건이 붙어야 한다.
  1. **제스처는 하나, 뜻도 하나**: "길게 누르면 옮기기"를 Task·Memo에 똑같이 쓴다. 방향마다 다른 동작이 붙는 스와이프는 받지 않는다.
  2. **눈에 보이는 대체 경로**: PC는 지금처럼 마우스를 올리면 ⋮⋮·×가 나온다. 모바일은 보관을 편집 시트 안의 버튼으로 할 수 있다. 제스처를 몰라도 못 하는 일이 없어야 한다.
  3. **누르는 동안 바로 반응**: 길게 누르면 행이 살짝 떠오르고, 기기가 지원하면 짧게 진동한다. 따로 설명하지 않아도 알 수 있어야 한다.
- 되돌릴 수 없거나 위험한 동작(보관·삭제)은 숨겨진 제스처에 맡기지 않는다. 옮기기처럼 실수해도 다시 옮기면 되는 동작만 맡긴다.

| B8 저장 상태 pill | **② 평소 숨김, 저장 중엔 작은 점, 실패 시에만 강조 + 다시 시도** | **+2** | 늘 보이던 요소 하나가 평소에는 사라진다. 헤더가 두 줄로 밀리던 문제(감사 3절)도 함께 없어진다.<br>"실패하면 빨간색"이라는 규칙 하나만 남아서 오히려 알아보기 쉽다. 실패 강조와 실행취소 토스트는 같은 곳·같은 모양을 쓴다. |

## 2. 안건 A 버그 수정 — UI를 늘리지 않기 위한 조건

원칙: **버그 수정은 사용자 눈에 "아무 일도 없었던 것처럼" 보여야 한다.** 실패를 알리는 수단은 B1·B8의 토스트와 pill 하나뿐이다.

| 조건 | 적용 |
|---|---|
| ① 새 대화상자·배너·오류 화면을 만들지 않는다 | 모든 실패는 같은 토스트("저장하지 못했어요 · 다시 시도") + pill 빨강으로만 알린다 |
| ② 실패하면 사용자가 하던 상태로 되돌린다(그 이상은 하지 않음) | A1: 입력창에 글을 되돌린다 / A2: 시트를 다시 열거나 닫지 않고, 시트 안에 한 줄 문구 + 저장 버튼을 "다시 시도"로 바꾼다 |
| ③ 보이지 않는 곳에서 해결할 수 있으면 보이지 않게 | A3: 앱으로 돌아오면 미저장 체크를 먼저 저장한 뒤 새로고침한다(표시 없음) / A4: 뒤쪽 저장이 실패하면 앞쪽 저장을 자동으로 되돌린다. "중복 표시" 같은 표식은 만들지 않는다 / A5: 원래 열 번호를 유지한다 |
| ④ "처리 중" 표시를 새로 만들지 않는다 | A8: 버튼을 흐리게 막는 대신 B9 낙관적 반영으로 행을 바로 없앤다. 같은 행을 두 번 누를 일이 구조적으로 사라진다 |
| ⑤ 요소를 빼서 고칠 수 있으면 빼서 고친다 | A9: Archive FAB 제거(B5) / A10: 내용 없이 편집이 끝나면 빈 메모를 자동 삭제(물어보지 않음) |
| ⑥ 같은 모양이면 같은 결과 | A6: 하위 할 일도 상위와 똑같이 "보관"으로 처리한다(영구 삭제 금지). B2에 따라 보관 버튼은 시트 안 한 곳에만 둔다 |
| ⑦ 상태 표시는 한 곳에서만 | A7: 저장 상태를 하나로 관리해 B8 pill에만 연결한다. 첫 로딩 스켈레톤은 **잠깐 보였다 사라지는** 것이므로 허용한다(CSS가 이미 있다) |
| ⑧ 오프라인 대기열(리서치 #11)을 만들 경우 | "대기 n건" 숫자는 평소에 숨긴다. 연결이 끊겼을 때만 pill에 보여준다. 설정 화면은 만들지 않는다 |

## 3. 이번 개선의 "심플함 예산"

### 늘 보이는 새 화면 요소: **최대 2개**
| 순위 | 후보 | 어디에 | 대신 빠지는 것 |
|---|---|---|---|
| 1 | **섹션별 "완료 n개" 접기 행**(B3) | 각 우선순위 섹션 맨 아래 | ⇅ 정렬 버튼, ⋯ 메뉴의 "완료 항목 보관", 줄 그어진 완료 행 여러 개 |
| 2 | **Archive 행의 상대 날짜 "3일 전"**(B14) | Archive 행 오른쪽 회색 글자 | (없음 — 그래서 2순위. 예산이 모자라면 먼저 뺀다) |

### 상황에 따라 잠깐 나타나는 요소: **최대 1종(기존 토스트 개선)**
- **공용 토스트**: 실행취소(B1·B11·분류) / 다시 시도(A·B8·B9) 두 가지 용도만. 성공 알림은 넣지 않는다. 지속 4~5초, `role=status`.

### 시트·메뉴 안 요소: **최대 2개**
- 편집 시트의 **"+ 하위 할 일"**(B7), 편집 시트의 **"보관"** 버튼(B2에서 × 이동)

### 새로 외울 규칙: **최대 2개**
- **"길게 누르면 옮기기"**(Task·Memo 공통, B2·B13)
- **"부모를 완료하면 하위도 완료"**(B11)

### 이번에 빠지는 요소(예산의 반대편)
모바일 행마다 있던 ⋮⋮·× (High만 20개 이상이면 40개 이상), ⇅ 버튼, 평소의 저장 pill, Archive FAB, 확인창 4종, 성공 토스트, Inbox 선택 모드에서의 행 액션(감사 B5), 섹션 헤더의 영어 대문자, 섞여 있던 우선순위 표기 3종
→ **늘어나는 요소 최대 2개, 빠지는 요소 10종 이상. 순감소가 이번 개선의 합격선이다.**

### 예산 밖이라 다음으로 미루는 후보(사용 데이터를 보고 결정)
- 접힌 부모의 "2/5" 회색 글자(리서치 #7) — 하위가 긴 사용 패턴이라 유용할 수 있다. 다만 1차 결과(B3 접기·B11)를 쓴 뒤 정한다.
- 하단 입력창 통일(B5 ②)

## 4. 반대(거부권 행사) 항목

| 항목 | 이유 |
|---|---|
| **B2 ③ 스와이프 = 보관** | 되돌리기 어려운 동작을 보이지 않는 제스처에 맡기게 된다. 긴 목록을 스크롤하다가 실수로 보관될 수 있다(TickTick 공식 블로그도 "실수로 완료되면 끄라"고 안내). 길게 누르기와 합치면 숨은 제스처가 2개가 되어 "제스처는 하나" 원칙을 깬다 |
| **B7 ③ 입력창 들여쓰기 문법** | 모바일 키보드에는 Tab 키가 없다. 외울 문법만 늘고 모바일에서는 쓸 수 없다 |
| **B13 ② 메모 드래그 핸들** | 카드마다 요소가 하나씩 늘어난다(14개). 이미 ×가 글자를 가리는 좁은 카드가 더 좁아진다 |
| **B12 ② 하단 탭바** | 하단에 입력창·선택 바·토스트·FAB가 이미 몰려 있다. 위치를 바꾸면 손에 익은 동선도 새로 익혀야 한다 |
| **B4 ② 탭 이름 한국어화** | 이미 외운 이름을 바꾸는 비용이 크다. "수집함" 같은 새 단어를 익혀야 한다 |
| 리서치 #9 체크박스 테두리에 우선순위 색 | 섹션이 이미 우선순위를 나타낸다. 행마다 색이 더해지면 같은 정보가 두 번 보이는 시각 소음이다 |
| 리서치 #16 메모 고정(pin) · #17 PC 인라인 편집 · #18 "오늘" 개념 | 각각 보드 배치 규칙, 편집 방식 2가지, 매일 초기화되는 새 개념을 추가한다. 1인 사용자가 매일 겪는 문제라는 근거가 없다 |
| 감사 C10 첫 사용 툴팁·길게 눌러 우선순위 선택 | 툴팁은 새 요소이고, 길게 누르기에 두 번째 뜻이 붙어 "제스처는 하나, 뜻도 하나" 원칙을 깬다 |
| 감사 C9 "30일 지난 항목 정리" 안내 | 사용자가 부탁하지 않은 알림이 생긴다. 날짜만 보이면 정리는 사용자가 판단한다 |
| 처리 중 행 흐림·스피너(감사 A8·E1 대안) | B9 낙관적 반영이 있으면 필요 없다. 같은 문제를 요소를 더해서 푸는 방식이다 |
| 마감일·알림·반복·태그·라벨·통계·효과음(리서치 3절) | 리서치 결론과 같다. 이번 범위에서 논의 자체를 하지 않는다 |
| **B6 인라인 `!!!` 문법** | 거부는 아니고 **보류**. 잘못 인식할 위험이 있고 매일 겪는 문제라는 근거가 없다 |
