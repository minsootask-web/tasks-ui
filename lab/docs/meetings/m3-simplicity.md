## 0. 결론 먼저 — "들여쓰면 하위" 한 가지만 더한다

> **입력창에서 한 줄 = 할 일 하나(R4 그대로). 들여쓴 줄 = 바로 위 줄의 하위.**

```
30일 할일            ← 상위
  자료 정리          ← 하위
  팀장 보고          ← 하위
경비 정산            ← 들여쓰지 않았으니 또 하나의 상위 (R4 그대로)
```

- **새 규칙: 1개**("들여쓰면 하위"). active.md 형식(`  - [ ]`), 화면의 하위 표시, 메모장·노션·메일 목록이 모두 이미 이렇게 생겼다. 그래서 "새로 외우는" 부담은 가장 작다. 2차에서 확보한 −2 중 1개만 쓴다. 장부로는 1차 +2 → 2차 −2 → 이번 +1이라 **규칙 예산 2개 중 1개가 남는다**.
- **늘 보이는 새 요소: 0개.** 남은 1개는 이번에도 쓰지 않는다.
- **R4와 충돌: 없다.** R4를 "줄마다 하나"에서 "줄마다 하나, 들여쓰면 하위"로 **넓힐 뿐**, 들여쓰지 않은 여러 줄의 결과는 오늘과 똑같다.
- **한 줄 입력만 쓰는 평소 사용 영향: 0.** 한 줄에는 "위 줄"이 없으므로 규칙이 작동할 수 없다. 아래 조건 C1~C3로 보장한다.
- **모바일: 같은 해석 규칙**(붙여넣기는 똑같이 묶음이 된다). 키로 묶음을 만드는 수단(Shift+Enter·Tab)만 PC 전용이다.

**합계: 0점** — 규칙 1개를 쓰는 대신 붙여넣기가 "보이는 그대로"가 되어 상쇄된다. 요소 0개, 규칙 예산은 1개 남음.

## 4. 추가 안건 F — 기본 보기를 "한 목록"으로 + 입력창 기본 🍅

전제: 요청은 채택한다. 파일의 `## 🔥 High` 등 섹션은 그대로 두고 **화면 보기만** 바꾼다.

### 4-0. 결론 먼저 — 요소는 줄고, 새 규칙은 0개
- **빠지는 것**: 섹션 헤더 3개, 섹션별 "완료 n개" 3개 중 2개, 빈 섹션 문구, 헤더의 개수 표시. 항목 수와 상관없이 **늘 보이는 요소 5개 이상이 줄어든다.**
- **늘어나는 것**: 체크박스 테두리 색(이미 있는 요소의 모양만 바뀜), 보기 전환은 ⋯ 메뉴의 한 줄(늘 보이지 않음). **늘 보이는 새 요소 0개.** 예산 1개는 이번에도 남긴다.
- **새 규칙 0개**: 드래그한 자리가 우선순위를 정하는 것은 지금 섹션 보기에서도 이미 그렇다(섹션 사이로 옮기면 우선순위가 바뀐다). 기본 🍅는 지금의 "마지막 값 유지"를 **대신하는** 규칙이라 개수가 늘지 않는다.
- **핵심 원칙: 두 보기는 순서가 같고, 헤더가 있느냐 없느냐만 다르다.** 보기를 바꿔도 항목이 한 줄도 움직이지 않아야 단순하다.

### 4-1. F1~F8 판정

| # | 선택 | 점수 | 근거 |
|---|---|---|---|
| **F1 한 목록의 순서** | **① 파일 순서 그대로**(🍅 항목들 → 🍋 → 🥝, 헤더만 뺀다) | **+2** | 섹션 헤더 3개가 빠지는데 순서는 그대로다. 보기를 바꿔도 아무것도 움직이지 않고, 저장 형식·봇과도 1:1로 맞는다.<br>② 추가한 순서는 파일에 시각 정보가 없어 새 데이터가 필요하다. 보기를 바꿀 때마다 순서가 뒤섞이고, 드래그로 정한 순서와도 따로 놀게 된다. 거부한다. |
| **F2 우선순위 표시** | **② 체크박스 테두리 색**(🍅 빨강 · 🍋 진한 노랑 · 🥝 초록). 상위 항목에만, 하위는 지금처럼 중립색 | **0** | 헤더가 빠지면 우선순위 단서가 어딘가에 남아야 한다. 이미 있는 체크박스의 색만 바꾸므로 요소는 늘지 않는다. **1차에서 거부했던 안을 조건이 바뀌어 받아들인다.** 1차의 거부 이유는 "섹션이 이미 우선순위를 보여 준다"였는데, 이제는 섹션이 없다.<br>① 행마다 🍅🍋🥝를 붙이면 High 20개 이상 기준 20~30개의 아이콘이 늘 보인다. 1차에서 ⋮⋮·×를 없애 넓힌 글 폭을 다시 줄이므로 프로젝트 전체에서 가장 큰 요소 증가가 된다. ③ 표시 없음은 🍅가 어디서 끝나는지 알 수 없게 되고 F4 드래그의 결과도 보이지 않는다.<br>조건: 노랑은 흰 배경에서 3:1 이상이 나오게 진하게 한다(WCAG 1.4.11). 체크박스 접근성 이름에 "🍅 High"를 넣는다. 섹션 보기에서도 같은 색을 써서 보기마다 다른 표시를 만들지 않는다. |
| **F3 보기 전환 장치** | **① ⋯ 메뉴 "우선순위별로 보기"**(체크 표시 한 줄), 기기에 기억 | **0** | 요청이 "원하면 분리해서"이므로 가끔 쓰는 기능이다. 가끔 쓰는 기능에 늘 보이는 자리를 주지 않는다. 이미 있는 메뉴에 한 줄이 늘 뿐이다.<br>② 헤더 아이콘과 ③ 탭 안 토글은 늘 보이는 새 요소이고 마지막 예산을 쓴다. 의미도 아이콘만으로는 알기 어렵다(⇅를 없앤 1차와 같은 이유). |
| **F4 한 목록에서 드래그** | **어디로든 옮길 수 있고, 놓은 자리의 우선순위를 따른다**(섹션 보기와 같은 규칙). 경계에서는 **바로 위 항목을 따른다**(맨 위는 🍅). **끄는 동안 테두리 색이 미리 바뀐다.** Cmd+Z로 무르기 | **0** | 지금 섹션 보기에도 있는 규칙이라 새 규칙이 아니다. 숨은 규칙이 되지 않도록 끄는 동안 바뀌는 테두리 색이 결과를 미리 보여 준다. 숨은 제스처도 늘지 않는다(길게 누르기 그대로).<br>"같은 우선순위 안에서만" 허용은 보이지 않는 벽이 된다. 경계가 화면에 없으니 왜 안 옮겨지는지 알 수 없어 버그처럼 느껴진다. 거부한다. |
| **F5 "완료 n개" 위치** | **목록 맨 아래 하나** | **+1** | 3개가 1개로 준다. 펼치면 완료 항목도 파일 순서(🍅→🍋→🥝)로 보이고, 테두리 색이 그대로 남아 어디서 왔는지 보인다.<br>"모두 보관"도 하나로 합쳐진다. 섹션 보기에서는 지금처럼 섹션마다 둔다. |
| **F6 입력창 기본 🍅** | **항상 🍅에서 시작하고, 다른 값을 고르면 그 한 번(Enter 1회, 묶음 포함)에만 적용한 뒤 🍅로 돌아간다.** 순환은 **🍅→🍋→🥝→🍅**(2차 D1의 🍋→🍅→🥝를 바꿈) | **+1** | "아무것도 안 누르면 High" 하나로 끝난다. 지금의 "마지막 고른 값이 남는다"는 사용성 1차에서 "처음엔 몰랐다"고 지적된 숨은 상태였는데 이게 없어진다.<br>D1이 🍋에서 시작한 건 기본값이 🍋일 때 1탭에 🍅로 가기 위해서였다. 기본이 🍅가 되면 읽는 순서·목록 순서와 같은 🍅→🍋→🥝가 가장 자연스럽다(🍋 1탭, 🥝 2탭). 🍋를 연달아 넣을 때 매번 1탭이 더 드는 비용은 감수한다. High가 20개 이상 쌓이는 실제 사용에서는 대부분 0탭이 된다. |
| **F7 새 항목 자리** | **현행 유지: 고른 우선순위의 끝**(🍅면 🍅 항목들의 끝). 화면 밖일 때만 스크롤 + 깜빡임(2차 결정 그대로) | **0** | 넣는 자리를 바꾸면(예: 맨 위) 섹션 보기와 규칙이 갈리거나 둘 다 바뀌어 새 규칙이 된다. 새 항목은 테두리 색과 깜빡임으로 찾을 수 있다.<br>조건: 화면 안에 보이면 스크롤하지 않는다. 연속 입력 중 화면이 계속 튀지 않게, 이어서 넣을 때는 첫 번째에만 스크롤하고 같은 자리 근처면 깜빡임만 준다. |
| **F8 묶음(E)과의 관계** | 묶음 = 한 번의 추가. 상위와 하위 전부 고른 우선순위로(E6), 끝에 함께 들어가고, 추가 뒤 🍅로 돌아간다(F6). 테두리 색은 상위에만(F2). 한 목록에서 상위를 드래그하면 하위도 함께 옮겨지고 함께 우선순위가 바뀐다 | **0** | E와 F의 규칙이 서로 새 예외를 만들지 않는다. 모두 "하위는 부모를 따라간다"는 기존 사실로 설명된다. |

**F 합계: +4.** 늘 보이는 요소 −5 이상, 새 요소 0, 새 규칙 0(대체 1).

### 4-2. F 거부권
| 항목 | 이유 |
|---|---|
| F2 ① 행마다 🍅🍋🥝 아이콘 | 항목 수만큼 아이콘이 늘어 1차에서 얻은 글 폭을 되돌린다. 프로젝트 최대의 요소 증가 |
| F3 ②·③ 헤더 아이콘 / 탭 안 토글 | 가끔 쓰는 전환에 늘 보이는 자리, 마지막 예산 소진 |
| F1 ② 추가한 순서 | 새 데이터 필요, 보기 전환 때 순서가 뒤섞임 |
| F4 "같은 우선순위 안에서만" 드래그 | 보이지 않는 경계에 막힘 = 버그처럼 느껴짐 |
| 우선순위 무리 사이 얇은 구분선·간격 | 사용자가 없애 달라고 한 "구분"을 다른 모양으로 되살리는 것. 테두리 색으로 충분하다 |
| "🍅만 보기" 같은 필터, 화면 크기에 따라 보기 자동 전환 | 요청 범위 밖이고 새 상태·새 규칙이 생긴다 |
| 마지막 고른 우선순위를 기기에 기억 | F6의 "기본 🍅" 하나로 끝내야 숨은 상태가 없다 |
