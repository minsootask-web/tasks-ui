# 3차 회의 — 프로덕트 디자이너 의견서: PC에서 묶음(부모 + 하위 여러 개) 한 번에 추가

- 작성: 프로덕트 디자이너 · 2026-10-20
- 사용자 요청: "pc에서 task 추가할 때 묶음 단위(예: '30일 할일' 하위에 여러가지 항목)를 한번에 추가"
- 읽은 자료: `m3-agenda.md`, `lab/index.html`의 입력창 처리(Enter = 추가, Task·Inbox는 줄바꿈을 막고 여러 줄 붙여넣기는 각각 상위 항목으로 나눔, 높이 38~98px)
- 결론 한 줄: **"오른쪽으로 들여 쓴 줄 = 바로 위 줄의 하위"** 하나로 끝낸다. Tab으로 치든, 붙여넣은 목록에 원래 들여쓰기가 있든 같은 규칙. 새 화면·새 버튼 없음.

## 0. 레퍼런스 확인 결과 (직접 열어 본 공식 문서 위주)

|---|---|---|---|

## E1. 묶음을 만드는 입력 방식 → **① 아웃라이너 방식 + ③ 들여쓰기 해석을 한 규칙으로 합침**

- 근거
  - ②("여러 줄이면 첫 줄이 부모")는 눈에 안 보이는 규칙이고, 메일에서 같은 급의 목록 5개를 붙여넣으면 **엉뚱하게 1 + 하위 4가 됨**. 이미 있는 R4(여러 줄 = 여러 상위)와도 정면으로 부딪힘 → 기각.
  - ④(따로 "묶음 추가" 시트)는 새 화면이라 원칙 위반 → 기각.
  - ①과 ③은 사실 같은 것: "들여 쓴 줄 = 하위". Tab은 들여쓰기를 **치는 방법**, 붙여넣은 공백·탭은 들여쓰기가 **이미 있는 경우**일 뿐. 규칙은 하나.
  - 새 규칙 예산(0)에 대해: tako에는 이미 "**오른쪽으로 끌면 하위**"(1차 B7)가 있고, active.md도 하위를 2칸 들여쓰기로 저장함. "오른쪽으로 밀면 하위"는 같은 비유를 키보드로 옮긴 것이라 **새로 외울 개념은 아님**. 그래도 심플함 수호자가 규칙 1개로 센다면, 사용자가 직접 요청한 기능이라 이 1개는 쓸 가치가 있다고 봄.
- 적용 범위: **Task 탭 입력창만.** Inbox·Memo는 현행 그대로(아래 실수 사례 참고).

### 키 동작 표 (PC, Task 탭 입력창)

| 키 | 지금 | 바뀐 뒤 |
|---|---|---|
| `Enter` | 추가 | 입력창의 **모든 줄을 한 번에** 추가(한 줄이면 지금과 같음) |
| `Shift+Enter` | 막혀 있음(아무 일 없음) | **새 줄.** 새 줄은 지금 줄의 들여쓰기를 그대로 이어받음(하위 줄에서 Shift+Enter → 또 하위 줄) |
| `Tab` | 다음 요소로 포커스 이동 | 커서가 **둘째 줄 이후**에 있을 때만: 그 줄을 하위로 들여쓰기. 이미 하위면 아무 일 없음(1단계까지). **입력창이 한 줄이거나 커서가 첫 줄이면 지금처럼 포커스 이동**(키보드 사용자 길 막지 않기) |
| `Shift+Tab` | 이전 요소로 포커스 이동 | 커서 줄이 하위면: 내어쓰기(상위로). 하위가 아니면 지금처럼 포커스 이동 |
| `Cmd+]` / `Cmd+[` (Win `Ctrl`) | 없음 | `Tab` / `Shift+Tab`과 같음(미리알림 습관용). 첫 줄 등 안 되는 자리에서는 아무 일 없음 |
| 하위 줄 맨 앞에서 `Backspace` | 글자 지움 | 먼저 **내어쓰기**만 함(아웃라이너 관례). 한 번 더 누르면 지금처럼 윗줄과 합침 |
| 여러 줄을 드래그로 고른 뒤 `Tab`/`Shift+Tab` | — | 고른 줄 전부 들여쓰기/내어쓰기(고른 범위에 첫 줄이 있으면 첫 줄만 빼고) |
| `Esc` | 입력창에서 나가기(2차 D3) | 그대로. 쓴 글은 지우지 않음 |
| 한글 조합 중 `Tab`·`Enter` | Enter는 무시 | Tab도 조합 중이면 무시(글자 확정이 먼저) |

### 입력창 안 들여쓰기 표시 방식·크기
- 들여쓰기는 입력창 안에 **실제 탭 문자 1개**로 넣고, CSS `tab-size: 3`(15px 글자에서 약 **24px**)로 보여줌. textarea라 줄마다 다른 꾸밈은 못 하지만, 탭 하나만으로 "안으로 들어간 줄"이 확실히 보임. 24px는 목록에서 하위 행이 들어가는 폭(드래그 하위 판정 24px)과 같은 숫자라 화면과 입력이 같은 리듬.
- 높이: 줄이 늘면 자동으로 커짐. Task 탭은 최대 **6줄(20px × 6 + 위아래 18px = 138px)**까지 보이고, 그 이상은 입력창 안에서 스크롤. (Memo는 지금처럼 4줄/98px.)
- 입력창이 2줄 이상이 되면 입력창 바로 위에 **안내 줄 1개**가 나타남(1줄로 돌아가면 사라짐 → 늘 보이는 요소가 아님, 예산 사용 0).
  - 위치: 입력창 둥근 상자 위 4px, 왼쪽 정렬(입력창 안쪽 글자 시작점과 맞춤), 높이 18px.
  - 글자: 12px, `--muted`, 숫자는 `tabular-nums`. 배경 없음(입력창 그라데이션 위에 그대로).
  - 문구(E3에서 자세히).

## E2. 붙여넣기와의 관계 → **들여쓰기·글머리 기호를 해석하되, 붙여넣기는 "입력창에 정리해서 보여주기"까지만. 추가는 언제나 Enter**

- 근거
  - Todoist·Things·Linear 모두 "붙여넣은 목록 = 여러 개"라 사용자 기대와 맞음. Things처럼 글머리 기호는 자동으로 떼어 "깔끔하게".
  - 붙여넣자마자 바로 추가하면 잘못 복사한 내용(긴 메일 전체 등)이 한 번에 쏟아짐. Todoist는 그래서 확인창을 띄우지만, tako는 **입력창이 곧 미리보기**라 확인창이 필요 없음: 붙여넣으면 정리된 모양이 입력창에 보이고, 맞으면 Enter.
  - R4(여러 줄 = 여러 상위)와의 공존: 들여쓰기가 없는 목록은 **지금과 똑같이** 각각 상위 항목. 들여쓰기가 있을 때만 하위가 됨 → R4는 이 규칙의 "들여쓰기 0개인 경우"일 뿐, 둘이 부딪히지 않음.

### 붙여넣을 때 정리 규칙

| 붙여넣은 줄 | 입력창에 들어가는 모양 |
|---|---|
| `- 장보기`, `* 장보기`, `• 장보기`, `· 장보기`, `◦ 장보기`, `‣ 장보기` | `장보기` (기호 뗌) |
| `1. 장보기`, `1) 장보기`, `가. 장보기` | `장보기` (번호 뗌) |
| `- [ ] 장보기`, `- [x] 장보기`, `☐ 장보기`, `☑ 장보기` | `장보기` (체크 표시 뗌, **모두 미완료로** 추가 — 계획을 붙여넣는 경우가 대부분) |
| 앞에 공백 2칸 이상 또는 탭이 있는 줄 | 하위(탭 1개)로 바꿈 |
| 가장 얕은 들여쓰기 | 상위로 맞춤(목록 전체가 들여쓰기돼 있어도 기준을 다시 잡음) |
| 하위의 하위(3단계 이상) | 모두 1단계 하위로 평평하게. 안내 줄에 `하위의 하위는 한 단계로 맞췄어요` |
| 빈 줄, 기호만 있는 줄 | 버림 |
| 첫 줄이 들여쓰기된 경우(위에 부모 없음) | 상위로 |
| 노션·메일에서 복사해서 일반 글에 들여쓰기가 없지만 서식 있는 목록(HTML 안의 목록)은 단계가 있는 경우 | HTML 목록의 단계를 씀 **(엔지니어 확인 필요: 노션 복사본의 일반 글에 탭이 남는지)** |
| `Cmd+Shift+V`(서식 없이 붙여넣기) | 위와 같은 정리 적용 |

- 붙여넣기 뒤 커서는 마지막 줄 끝. 입력창이 그 내용만큼 커지고 안내 줄이 바로 보임.

## E3. 추가 전 미리보기·안내 → **입력창이 곧 미리보기(들여쓰기가 보임) + 2줄 이상일 때만 안내 줄 1개**

- 근거: 버튼을 늘리지 않으면서 "Enter를 누르면 무엇이 생기는지"를 숫자로 보여줘야 대량 오입력을 막을 수 있음. Things의 줄 수 상한, Todoist의 "Add X tasks?" 숫자 안내를 **확인창 없이** 같은 정보로 바꾼 것.
- 안내 줄 문구(쉬운 말, 우선순위 이모지로 어디에 들어갈지까지)

| 상황 | 문구 |
|---|---|
| 하위 없는 여러 줄 | `🍋 Medium에 할 일 3개 · Enter로 추가` |
| 부모 1 + 하위 | `🍋 Medium에 할 일 1개 + 하위 4개 · Enter로 추가` |
| 부모 여러 묶음 | `🍅 High에 할 일 2개 + 하위 5개 · Enter로 추가` |
| 첫 줄에서 Tab을 눌렀을 때(2초) | `첫 줄은 묶음의 제목이에요. 둘째 줄부터 Tab으로 넣어요` |
| 하위에서 Tab을 또 눌렀을 때(2초) | `하위는 한 단계까지예요` |
| 줄 수 초과 | `한 번에 50줄까지 넣을 수 있어요 (지금 72줄)` — 글자 `--accent-strong`, 추가 버튼 비활성 |
| 처음 2줄이 되었을 때(PC, 기기당 3번까지만 덧붙임) | `… · Tab으로 하위 만들기` |

- 마지막 줄 "Tab으로 하위 만들기"는 발견성 장치. 별도 툴팁·토스트 없이 이미 뜨는 안내 줄 끝에 붙고 3번 뒤엔 안 보임.

### 최대 줄 수
- **한 번에 50줄**(부모·하위 합계). 근거: Things는 100줄 상한. tako는 한 사람이 쓰는 목록이고 섹션 하나에 50개가 넘으면 이미 정리할 시점이라 절반으로. 넘으면 **글은 그대로 두고** 추가만 막음(쓴 글 보존 원칙).
- 한 줄 최대 글자 수는 지금과 같게(따로 정하지 않음).

## E4. 모바일에서는 → **같은 규칙, 다만 "치는 방법"은 붙여넣기만. 새 버튼은 만들지 않음**

- 근거: 규칙이 기기마다 다르면 그게 또 하나의 규칙. 붙여넣은 목록의 들여쓰기는 키보드가 아니라 **글 자체에 있는 정보**라 모바일에서도 똑같이 해석하면 됨.
- 근거: 모바일에 들여쓰기 버튼(→)을 넣으면 늘 보이는 요소가 늘거나 입력창 툴바가 생김. 모바일에서 하위를 여러 개 만드는 길은 이미 편집 시트의 `+ 하위 할 일 추가`(Enter마다 이어 쓰기)가 있음.
- 스펙
  - 휴대폰: 키보드 Enter = 지금처럼 추가(보내기). 줄바꿈을 직접 칠 수는 없음. 들여쓰기가 있는 목록을 **붙여넣으면** PC와 같은 정리·안내 줄·추가.
  - 하드웨어 키보드가 붙은 태블릿: Tab·Shift+Enter가 그대로 동작(PC와 같음, 별도 처리 없음).
  - 모바일 안내 줄 문구에는 "Tab으로 하위 만들기"를 붙이지 않음.

## E5. 실수 복구 → **묶음 전체가 되돌리기 1번. 되돌리면 글이 입력창으로 그대로 돌아옴**

- 근거: 여러 줄 추가는 한 번에 화면이 크게 바뀌고, 잘못 붙여넣는 사고가 실제로 생기는 동작. 그래서 2차 결정(한 개 추가는 토스트 없음, Cmd+Z만)의 예외로 **2개 이상 한 번에 추가할 때만** 되돌리기 토스트를 띄움 — "토스트는 되돌리기·다시 시도만" 원칙 안에 있음.
- 스펙
  - 토스트: `할 일 1개와 하위 4개를 추가했어요 · 되돌리기` (하위 없으면 `할 일 3개를 추가했어요 · 되돌리기`), 5초.
  - `Cmd/Ctrl+Z`(입력창 밖에서) 한 번 = 묶음 전체 되돌리기. 토스트가 사라진 뒤에도 마지막 동작이면 동작.
  - 되돌리면: 추가된 행이 모두 C1 모션(투명 120ms → 자리 유지 300ms → 접기 200ms)으로 빠지고, **원래 쓴 묶음(들여쓰기 포함)이 입력창에 다시 채워짐**. 입력창에 이미 다른 글이 있으면 그 글 아래에 줄바꿈으로 이어 붙임. → 한 줄만 고쳐서 다시 Enter 가능.
  - 저장 실패: 묶음 전체를 실패로 보고 행을 거둔 뒤 **들여쓰기까지 그대로** 입력창에 되돌림 + `저장하지 못했어요 · 다시 시도`. 일부만 저장된 상태(부모만 있고 하위 없음)를 화면에 남기지 않음(원칙 2 "한 곳에만, 온전하게").

## E6. 우선순위 → **묶음 전체가 입력창 우선순위 버튼의 섹션으로**

- 근거: 하위 할 일은 파일에서 부모 아래 들여쓰기로 저장되고 자기 우선순위가 없음. 줄마다 우선순위를 고르게 하면 문법(B6 `!!!`, 폐기됨)이 다시 필요해짐.
- 스펙
  - 안내 줄 맨 앞 이모지가 들어갈 섹션을 보여줌(`🍅 High에 …`). 우선순위 버튼을 누르면 안내 줄도 바로 바뀜.
  - 부모 여러 묶음이어도 전부 같은 섹션, 입력 순서 그대로 섹션 끝에 붙음.
  - 추가 뒤: 첫 부모 행으로 부드럽게 스크롤(화면 밖일 때) + 추가된 모든 행 600ms 깜빡임. 새 부모는 **펼친 상태**로 보여줌(방금 넣은 하위가 보여야 안심).

## F1. 한 목록의 순서 → **① 파일 순서 그대로 (High 항목들 → Medium → Low, 헤더만 없앰)**

- 근거: ② 추가한 순서는 파일에 시각 정보가 없어 만들 수 없고, 보기 전환 때마다 크게 뒤섞임.
- 스펙: 우선순위가 바뀌는 경계에 **헤더·줄 없음**. 대신 경계에서만 행 사이 간격을 2px → **10px**로 벌림(새 요소 아님, 여백만). 과일 이모지가 바뀌는 자리 + 숨 쉴 틈으로 묶음이 자연스럽게 읽힘.

## F3. 보기 전환 장치 → **① ⋯ 메뉴 항목 (기기에 기억)**
- 근거: Todoist(Display 메뉴), 미리알림(보기 메뉴) 모두 메뉴 안. 헤더 아이콘(②)은 **늘 보이는 요소 1개**를 써 버리고, 토글(③)도 같음. 사용자가 "원하면 분리"라고 했으니 자주 바꾸는 장치가 아님.
- 스펙
  - 위치: ⋯ 메뉴의 `완료 항목 보관` 바로 아래(구분선 위, Task 탭에서만 보임).
  - 문구는 다크 모드 항목처럼 **지금 누르면 될 상태**로 바뀜:
    - 한 목록일 때: 아이콘 `🍅` + `우선순위별로 나눠 보기`
    - 나눠 보기일 때: 아이콘 `☰` + `한 목록으로 보기`
  - 누르면 메뉴 닫힘 → 목록이 `--dur`(200ms)에 헤더가 펼쳐지거나 접히며 바뀜(항목 순서는 그대로라 화면이 튀지 않음). 지금 보고 있던 첫 행이 화면 같은 높이에 남도록 스크롤 보정. 토스트 없음.

## F4. 한 목록에서 끌어 옮기기 → **다른 우선순위 사이로도 옮길 수 있고, 놓은 자리의 우선순위로 바뀜. 대신 끄는 동안 바뀔 과일을 미리 보여주고, 바뀌었으면 되돌리기 토스트**
- 근거: 지금 나눠 보기에서도 "다른 섹션으로 끌면 우선순위가 바뀜"이 이미 있는 규칙 → 한 목록에서도 같게 하면 **새 규칙이 아님**. 같은 우선순위 안에서만 허용하면 경계에서 손이 막혀 "왜 안 되지?"가 됨.
- 근거: 한 목록은 경계가 헤더로 보이지 않으니, 끄는 중에 결과를 보여주고(미리보기) 놓은 뒤 되돌릴 수 있어야 함(우선순위 변경은 Inbox 분류와 같은 무게 → 같은 토스트).
- 스펙
  - 놓을 자리 판정: 끼어드는 선의 **바로 위 행**의 우선순위를 따름. 맨 위에 놓으면 첫 행의 우선순위. (경계 = High 끝과 Medium 첫 행 사이에 놓으면 High의 끝 — "추가는 섹션 끝" 현행과 같은 방향)
  - 미리보기: 끄는 고스트 안의 과일이 놓일 자리 우선순위로 바뀜 + 바뀌는 순간 `done-bump`(120ms 1.15배). 같은 우선순위면 그대로.
  - 놓은 뒤 우선순위가 바뀌었으면: 토스트 `🍋 Medium으로 옮겼어요 · 되돌리기`(5초). 순서만 바뀌었으면 토스트 없음(2차 D2, Cmd+Z만).
  - 하위로 넣기(오른쪽 24px): 현행 그대로. 부모의 우선순위를 따르므로 고스트의 과일은 부모 것으로 바뀌고, 우선순위가 달라졌으면 같은 토스트.
  - 완료 항목은 끌지 않음(현행).

## F5. "완료 n개" 접기 → **한 목록 맨 아래에 하나**
- 스펙: 목록 마지막 미완료 행 아래, 모양·크기·문구 현행 그대로(`완료 7개 ›`, 36px). 펼치면 완료 항목이 **파일 순서대로**(High 완료 → Medium → Low) 행마다 흐린 과일(.45)과 함께. 펼침 상태는 보기별로 따로 기억(한 목록 1개 / 나눠 보기 섹션 3개).
- 머무름 800ms 뒤 접힐 때 목록 맨 아래까지 멀 수 있으므로 접기 행 숫자 튐(현행)만 쓰고 스크롤은 하지 않음.

## F6. 입력창 기본 우선순위 → **앱을 열 때마다 🍅 High로 시작. 쓰는 동안은 고른 값 유지. 순환은 🍅 → 🍋 → 🥝**
- 근거: 사용자가 기본 High를 요청. 2차 D1에서 🍋→🍅→🥝로 바꾼 이유는 "기본 🍋에서 High까지 한 번"이었으므로, 기본이 🍅가 되면 **머릿속 순서(High → Medium → Low)대로** 도는 게 가장 자연스러움.
- 근거: 앱을 열 때마다 🍅로 돌아가야 "기본은 High"가 지켜짐. 연달아 넣을 때 매번 돌아가면 같은 우선순위 여러 개 넣기가 불편하므로 그동안은 유지.
- 스펙
  - 🍅로 되돌아가는 때: 앱을 새로 열 때, 앱을 떠났다가 **30분 넘게** 지나 돌아올 때.
  - 유지되는 때: 추가 뒤, 탭 전환, 30분 안의 앱 전환.
  - 순환: 🍅 High → 🍋 Medium → 🥝 Low → 🍅. 바뀔 때 이모지 120ms 튐(2차 D1 스펙 그대로).
  - 접근성 이름: `우선순위 🍅 High · 누르면 🍋 Medium`.

## F7. 새 항목이 들어가는 자리 → **현행 유지(그 우선순위의 끝 = 한 목록 중간) + 화면 밖이면 스크롤·깜빡임**
- 근거: 들어가는 자리 규칙을 바꾸면 나눠 보기와 결과가 달라지고, 봇의 추가 위치와도 어긋남 → 새 규칙. 대부분 High 묶음은 목록 위쪽이라 화면 안에서 깜빡임만으로 보임.
- 스펙: 2차 결정 그대로 — 화면 밖이면 그 행으로 300ms 부드럽게 스크롤 + 600ms 깜빡임, 화면 안이면 깜빡임만. 한 목록에서는 새 행의 과일도 함께 깜빡여 "High 끝에 들어갔다"가 보임.
- 양보 가능: 써 보고 "중간이라 못 찾겠다"면 다음 회차에 "High 맨 위(=목록 맨 위)"를 검토.

## F8. 묶음 추가(E)와의 관계 → **그대로 맞물림. 기본 🍅라 묶음도 기본은 High 끝**
- 스펙
  - E3 안내 줄 첫 이모지가 입력창 값을 따르므로 기본 문구는 `🍅 High에 할 일 1개 + 하위 4개 · Enter로 추가`. (위 E3 표의 `🍋 Medium` 예시는 기본값이 🍅로 바뀌면 `🍅 High`가 기본)
  - 한 목록에서 묶음이 들어가면 부모 행에만 과일, 하위는 과일 없이 들여쓰기 → 묶음이 한 덩어리로 보임.
  - E5 되돌리기·E6 섹션 규칙 변화 없음.

## F 실수 사례

| # | 실수 | 동작 |
|---|---|---|
| 1 | 한 목록에서 순서만 바꾸려다 경계를 넘김 | 고스트 과일이 바뀌는 걸 보고 멈출 수 있음. 놓아도 되돌리기 토스트 1번 |
| 2 | 나눠 보기를 켠 걸 잊음 | 메뉴 문구가 `한 목록으로 보기`로 보여 현재 상태를 알 수 있음. 섹션 헤더가 보이는 것 자체가 표시 |
| 3 | 🍋를 골라 둔 채 다음 날 열었음 | 🍅로 돌아가 있음(30분 규칙) |
| 4 | 하위만 다른 우선순위로 바꾸고 싶음 | 지금과 같이 불가(하위는 부모를 따름). 시트에서 부모 우선순위를 바꾸면 묶음 전체가 이동 |
| 5 | 완료 항목을 찾음 | 맨 아래 `완료 n개` 하나만 보면 됨(한 목록의 장점) |

## F 예산 정리
- 늘 보이는 새 요소: **행마다 과일 이모지**를 1개로 셀 수 있음 → 남은 1개를 여기 씀. 대신 나눠 보기 헤더 3개(🍅 High·🍋 Medium·🥝 Low)와 섹션별 `완료 n개` 2~3개가 기본 화면에서 빠져 **화면 요소는 순감소**.
- 새 규칙: 0 (끌어서 우선순위 바꾸기는 기존 규칙, 보기 전환은 메뉴 옵션).
