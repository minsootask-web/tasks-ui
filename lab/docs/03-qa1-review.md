### XSS·예외 삼킴 점검 결과
- XSS: `innerHTML`로 들어가는 사용자 데이터는 `esc`/`highlightMeta`를 거침(1801, 2743-2746, 2825). 메모·Inbox·토스트는 `textContent`. **문제 없음.** 다만 `esc`(818)는 `"`·`'`를 바꾸지 않으므로 앞으로 속성값(`title="${…}"`)에 쓰면 안 됨.
- 예외 삼킴: `refresh` 3618 `flushAll().catch(()=>{})`와 `retryFailedSaves` 2563은 스토어가 상태를 따로 보고하므로 괜찮음. 문제는 Q16(keep 연산이 조용히 버려짐), Q14-②(지울 대상이 없어도 성공).

## 3. 마크다운·봇 호환 확인 (문제 없음 항목)
- active.md: 섹션 헤더 문자열 `SECTION_KEYS` 718 그대로. 새 줄은 `- [ ] text`, 하위는 2칸 단위(`adjustBlockIndent` 1563). 헤더가 없으면 정해진 순서 위치에 다시 만듦(1438-1450, 앞에 빈 줄은 넣지 않음 — 보기만 다름). 숨은 표시·주석 없음 → 봇 `cmd_list`/`cmd_done` 호환.
- inbox.md: `- text\n`을 끝에 붙임(`opInboxAppend` 1179-1184). 봇의 `rstrip() + "\n- text\n"`과 섞여도 형식 유지.
- memos.json: col 0~2, order 숫자(소수 가능), `x/y`는 읽을 때만 하위 호환(1966-1977). 초안(`_draft`)은 저장할 때 걸러짐(1158).
- archive.json: 새 필드 `parent`만 추가. 렌더는 `block`/`text`가 없어도 동작(1795-1799).
- 봇 동시 쓰기: 봇은 409를 재시도하지 않으므로, 앱이 먼저 저장하면 봇 쪽이 실패할 수 있음(봇 문제, 이번 범위 밖). 앱 쪽은 409를 받으면 최대 2번 재적용.
