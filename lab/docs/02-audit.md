# tako 휴리스틱 감사 (lab/index.html)

- 대상: `tasks-ui/lab/index.html`(3,065줄) + `lab/mock-github.js`(지연 350ms)
- 방법: 코드 전체 정독 + 브라우저 패널에서 모바일(375×812, 다크)·데스크톱(라이트) 직접 조작, `__takoMockFail`·fetch 래핑으로 실패 재현
- 표기: 줄번호는 `lab/index.html` 기준. 빈도 = 이 기능을 얼마나 자주 쓰는지(상: 매일 여러 번 / 중: 주 몇 번 / 하: 가끔)

## 2. 유지해야 할 점 (심플함의 핵심)

1. **단일 입력 → 바로 목록**: Task 하단 입력창은 Enter만 누르면 추가되고 입력창이 유지돼 연속 입력이 빠름. 한글 IME 조합 중 Enter 오입력 방지(2848-2939)가 잘 되어 있음.
2. **체크 낙관적 업데이트 + 연속 클릭 디바운스**(2405-2453): 가장 자주 하는 동작이 즉시 반응함. 체크 순간 pop 애니메이션도 가볍고 기분 좋음.
3. **3단 우선순위만 있는 단순 구조**: 마감·태그·프로젝트 없이 섹션 3개 + 하위 할 일. 메타 `(~10/21)`가 글 안에 흐리게 강조되는 방식(807)은 입력 부담이 없음.
4. **보관함을 통한 안전망**: 상위 항목 삭제는 보관으로 처리되고 복구할 수 있음. 일괄 보관에 "실행취소" 토스트가 있음 → 이 패턴을 넓히면 확인창을 줄일 수 있음.
5. **Inbox 분류 동선**: 행마다 H/M/L 한 번으로 Task에 보냄(표기만 🍅🍋🥝로 통일하면 됨). 여러 개 골라 한 번에 보내기도 됨.
6. **마크다운 원본 유지**: active.md 형식을 그대로 읽고 써서 봇·Skill과 호환됨. 줄 위치를 원문으로 다시 찾는 안전장치(1136-1163)와 섹션 헤더 재생성(1103-1116)도 있음.
7. **차분한 Notion풍 팔레트와 다크/라이트 지원**, 시트의 포커스 가두기·Esc·포커스 복귀(2725-2766), 우선순위 라디오의 roving tabindex.
8. **PC에서는 hover에만 행 액션 노출**: 데스크톱은 깔끔함(모바일만 B2 문제).
9. 메모 보드의 노란 스티커 메타포는 Task와 시각적으로 확실히 구분돼 "생각 덤프" 용도가 분명함.

## 3. 스크린샷 관찰 요약

- **첫 로딩(모바일·다크)**: 탭 아래가 완전히 빈 화면인데 표시는 "동기화됨". 1~2초 뒤 목록이 나타나면서 헤더 메타가 두 줄로 바뀌어 레이아웃이 밀림(날짜·진행률 줄 + 저장 상태 줄).
- **Task(모바일)**: 행마다 오른쪽에 ⋮⋮ ×가 세로로 반복돼 회색 기둥처럼 보임. 긴 항목("신규 입사자 온보딩… (https://…)")은 4줄로 접힘. 하단 입력창 그라데이션이 마지막 행을 자연스럽게 덮고, 본문 아래 여백 108px로 끝까지 스크롤하면 다 보임.
- **Inbox**: H/M/L 글자 버튼 3개 + ×가 행 폭의 약 45%를 차지함. 선택하면 붉은 배경이 생기고 하단 바가 올라오는데, FAB가 바 위로 반쯤 걸쳐 잘려 보임.
- **Memo(모바일 2열)**: 노란 카드는 보기 좋지만 × 원형 버튼이 글자 위에 겹침. 카드 위에서 스크롤할 수 없음(B1).
- **Archive**: 🍅/🥚/🥝 배지 + 글 + ↺ ×. 날짜가 없어 언제 보관했는지 알 수 없음. FAB를 누르면 "Inbox에 추가" 시트가 열려 맥락이 맞지 않음.
- **시트**: 하단 시트 + 어두운 배경, 취소/저장이 같은 폭이라 깔끔함. 우선순위 칸은 High/Medium/Low + 색 점이라 다른 화면의 이모지와 다름.
- **데스크톱(라이트)**: hover 전에는 행 액션이 숨겨져 정돈돼 보임. 회색 보조 글자(날짜·개수·"비어 있음")가 흐려 읽기 힘듦(D4).
